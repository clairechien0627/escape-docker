關於「Falco 偵測率」與「規則覆蓋率」的解讀： 偵測率代表「該次執行期間，lab-api 是否收到至少一筆來自 Falco 的告警」（透過 /api/lab/falco-webhook 即時轉發）。 規則覆蓋率則是更細緻的指標：該場景 falco_rule_refs 中，有對應且已啟用的 Falco 規則 （見 falco/README.md 第 2 節對照表），曾在任一次執行中被 實際命中的比例；滑鼠移到長條上可看到已觸發的規則名稱。— 代表該場景沒有對應的可量測規則，或尚未執行過。 偵測延遲是該場景所有「曾命中可量測規則」的執行中， 從 POST /api/lab/runs 發起時間到第一筆對應 Falco 告警送達 lab-api 的時間差平均值——兩端時間都採用 lab-api 自己的時鐘，避免 Falco container 與 lab-api 之間的時鐘飄移影響量測。

2026-06-14：把 escape-falco 接進常駐 stack 後，先前記錄 「container context 解析不到、規則不會觸發」的案例（room6 的 Docker Socket Accessed From Container、 Unexpected Child Process In Container Via Docker Exec， secret-b 的 Docker Save Or History Executed 等）已能正確 觸發，詳見 troubleshooting/falco-container-context-not-resolved.md 第 8 節與 falco/README.md 第 4.6 節。殘留限制：因 container.name/container.id 在告警輸出中仍為 null，run.alerts 以時間窗口（而非 container）關聯，規則覆蓋率的「已觸發規則」可能包含同一時段其他房間 /host 程序產生的雜訊規則。
